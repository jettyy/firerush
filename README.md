# 파이어러시 (firerush)

엑셀에서 복사한 주제 목록을 붙여넣으면, AI가 주제마다 블로그 글과 썸네일을 만들어
**네이버 블로그 에디터에 옮겨 적고 임시저장**해 주는 로컬 대시보드입니다.

- 글 생성: `claude -p` (Claude Code CLI 헤드리스 모드) → **구독 요금제 그대로 사용**, 토큰 종량 과금 없음
- 모델 선택: 대시보드에서 드롭다운으로 고름 (Opus 5 / Sonnet 5 / Haiku 4.5 …). 어떤 모델이 썼는지 작업표에 기록됨
- 순위 글: 주제에 `TOP100`, `50가지` 처럼 개수가 있으면 **항목 전부를 표로** 만듦 (구간을 나눠 생성 → 누락 없음)
- 추가 지침: 프롬프트 맨 앞·맨 끝에 두 번 들어가고 기본 규칙보다 **우선 적용**
- 참고 예시: "이런 식으로 써줘" 할 글을 첨부하면 문체와 구성을 참고
- 썸네일: AI가 문구·색상을 설계 → HTML 템플릿 렌더링 → Playwright 스크린샷 (추가 비용 0원)
- 삽입 위치: **제목 → 도입부 → 썸네일 → 본문** 순서라 이미지가 글 상단 1/3 안에 들어갑니다
- 네이버 접속: Playwright (크로미움이 없으면 자동 설치)
- 로그인: 대시보드 버튼 → 실제 브라우저 창에서 직접 로그인 → 세션을 이 컴퓨터에 저장
- 발행은 하지 않습니다. **임시저장까지만** 하고, 최종 검토·발행은 사람이 합니다.

## 준비물

| 항목 | 확인 |
|---|---|
| Node.js 20 이상 | `node -v` |
| Claude Code CLI | `claude --version` — 없으면 `npm install -g @anthropic-ai/claude-code` 후 `claude` 를 한 번 실행해 구독 계정으로 로그인 |
| 네이버 블로그 계정 | 로그인은 프로그램이 띄운 창에서 직접 합니다 |

> 이 프로그램은 **사용자 PC에서 실행**해야 합니다. 네이버 로그인에 실제 브라우저 창이 필요하고,
> 세션도 사용자 PC에 저장되기 때문입니다.

## 설치와 실행

```bash
npm install
npm run setup      # claude CLI 확인 + 크로미움 준비 (선택, 첫 실행 시 자동으로도 됩니다)
npm start          # → http://localhost:3000
```

포트를 바꾸려면 `PORT=4000 npm start`.

## 사용 흐름

1. **네이버 로그인** — [네이버 로그인 창 열기]를 누르면 브라우저 창이 뜹니다.
   아이디·비밀번호(+2단계 인증)를 그 창에 직접 입력하세요.
   로그인이 확인되면 세션이 `data/browser-profile/` 에 저장되고, 다음부터는 재로그인이 필요 없습니다.
   블로그 아이디는 자동으로 찾지만, 못 찾으면 입력칸에 직접 넣어 주세요.
2. **주제 붙여넣기** — 엑셀에서 주제 열을 복사해 텍스트 영역에 그대로 붙여넣습니다.
   한 줄에 주제 하나로 인식하고, 탭으로 나뉜 경우 첫 열만 씁니다.
   머리글(`주제`, `제목` 등)과 중복은 자동으로 걸러냅니다. 100개든 그대로 붙여넣으면 됩니다.
3. **지침 & 예시** — AI에게 꼭 지키게 할 내용을 적고, 참고할 예시 글을 올립니다. (아래 설명 참고)
4. **설정** — 사용할 AI 모델, 말투, 분량, 소제목 개수, 썸네일 스타일, 대기 시간 등을 조정합니다.
5. **실행** — 주제를 하나씩 순서대로 처리합니다.
   진행 상황·실패 사유·생성된 썸네일이 표에 실시간으로 표시됩니다.
   일시정지/중지/개별 재시도가 가능합니다.
6. **확인** — 네이버 블로그 글쓰기 화면의 **저장 목록(임시저장)** 에서 결과를 확인하고 발행하세요.

## 결과물이 남는 곳

```
data/
├── settings.json          설정
├── jobs.json              작업 목록 (껐다 켜도 유지)
├── naver-session.json     로그인 상태 요약
├── naver-cookies.json     네이버 로그인 쿠키 백업 (이 컴퓨터에만, git 에 올라가지 않음)
├── browser-profile/       네이버 로그인 세션 (이 폴더를 지우면 재로그인 필요)
├── examples/              올려둔 참고 예시 글
├── thumbnails/            생성된 썸네일 PNG
├── screenshots/           자동화 실패 시 화면 캡처
└── posts/<주제-id>/       post.json · preview.html · 썸네일
```

`data/` 는 git에 올라가지 않습니다. 네이버 자동화가 실패해도 글 자체는
`data/posts/` 에 남으니 `preview.html` 을 열어 수동으로 옮길 수 있습니다.

## 설정 항목

| 항목 | 설명 |
|---|---|
| 사용할 AI 모델 | 본문을 쓰는 모델. 글 품질이 여기서 갈립니다 (권장 Opus 5) |
| 표의 행을 채울 모델 | 표의 행만 채우는 모델. 기본 Sonnet 5 — 본문 품질과 무관합니다 |
| 웹 검색 | 글을 쓰기 전에 실제 자료를 검색할지. 켜면 수치와 출처를 인용할 수 있지만 글 하나에 1~3분 더 걸립니다 |
| 페르소나 사용 | 정해진 화자의 1인칭 경험담으로 쓸지. 끄면 화자 설정과 금지 소재 검사가 빠집니다 |
| 닉네임 / 화자 / 생활 | 프롬프트 맨 앞에 들어갑니다. 글 전체의 톤과 배경을 결정하는 가장 중요한 설정입니다 |
| 절대 쓰지 않을 소재 | 프롬프트에서 금지되고, 글에 나오면 품질 검사에서도 걸러집니다 |
| 말투 검사 기준 | `독백체`(~했네요/~더라고요) · `존댓말`(~습니다) · `해요체`(~해요) |
| 어조 설명 | 자유 서술. 프롬프트에 그대로 들어갑니다 |
| 목표 분량(공백 제외) | 품질 검사의 최소 글자 수 기준입니다. 못 채우면 자동으로 더 써서 다시 냅니다 |
| 소제목 개수 / 독자 | AI 프롬프트에 그대로 반영됩니다 |
| 선정 기준 단락 | 순위·비교 글 서두에 "왜 이 항목들을 골랐는지" 밝히는 단락을 넣을지 |
| 순위 글 표 크기 | 개수를 안 쓴 "OO 순위" 주제에서 몇 개까지 채울지 (기본 100, 최대 300) |
| 썸네일 스타일 | `auto`(AI가 선택) · `bold` · `gradient` · `minimal` · `editorial` |
| 썸네일 크기 | 기본 1200×630. 실제 파일은 2배 해상도로 저장됩니다 |
| 본문 강조 카드 | 본문 1/5·중간·4/5 지점에 카드 이미지 3장을 넣을지 (항상 무료) |
| 썸네일 AI 생성 | 상단 썸네일을 이미지 API로 만들지 (글 1편당 1장, 유료) |
| 썸네일 만드는 방식 | `AI가 한글까지 통째로` (기본) / `배경만 AI, 한글은 프로그램이` |
| 구글 API 키 | AI Studio 키. `data/settings.json` 에만 저장됩니다. 모델은 자동으로 골라집니다 |
| 품질 검사 자동 보정 | 검사에 걸리면 그 항목만 짚어 자동으로 다시 쓰게 할지 |
| 보정 재시도 횟수 | 자동 보정을 몇 번까지 시도할지 (호출이 늘어나므로 1회 권장) |
| 실패 시 저장 차단 | 끝내 통과 못 하면 저장하지 않고 실패로 남길지 (기본은 "저장은 하되 표시만") |
| 글 사이 대기 | 기본 30~90초 무작위. 연속 자동화를 완화합니다 |
| 재시도 횟수 | 실패한 주제를 자동으로 다시 시도하는 횟수 |
| 브라우저 창 숨기기 | 헤드리스 실행. 네이버는 창을 띄우는 편이 더 안전합니다 |

설정 파일에서만 조정 가능한 항목:

- `claude.command` — `claude` 실행 파일 경로 (PATH에 없을 때)
- `run.chromiumPath` — 이미 설치된 크롬/크로미움 경로 (환경변수 `CHROMIUM_PATH` 도 가능)

## 추가 지침 (가장 중요한 설정)

대시보드 **3번 칸**에 쓰는 내용입니다. 입력하면 자동으로 저장됩니다.

여기 쓴 지침은 프롬프트의 **맨 앞**과 **맨 끝**에 두 번 들어가고,
"기본 규칙과 충돌하면 이 지침을 따르라"고 명시됩니다. 그래서 기본 설정(말투, 문단 길이 등)과
반대되는 요구도 지침이 이깁니다.

한 줄에 하나씩 쓰면 더 잘 지킵니다.

```
반드시 실제 경험담처럼 쓸 것
각 소제목 끝에 물음표를 붙일 것
마지막에 체크리스트를 넣을 것
```

AI 는 지침을 어떻게 반영했는지 `guidelineCheck` 로 스스로 보고하고, 그 내용이 작업표의
**지침 ✓** 배지(마우스를 올리면 내용이 보입니다)와 진행 로그에 남습니다.

## 글쓰기 지침 — 누가, 어떤 말투로 쓰는가

이 프로그램은 정보를 나열하는 백과사전 글이 아니라, **정해진 한 사람이 직접 겪고 쓴 글**을
만듭니다. 네이버가 높게 치는 것이 "사람이 쓴 글"이라는 신호이기 때문입니다.
화자 설정과 말투, 금지 소재는 `src/content/persona.js` 한 곳에 있고, 설정 화면에서
바꿀 수 있습니다.

- **화자**: 기본값은 "30대 후반 직장인이자 남매 쌍둥이를 키우는 아빠"입니다.
  주제가 무엇이든 퇴근, 육아, 주말 같은 일상이 배경으로 깔립니다 (다만 주제를 잡아먹지 않게 스치듯).
- **말투**: 혼잣말에 가까운 덤덤한 구어체. "~했네요", "~더라고요", "~인 것 같습니다".
  가르치려 드는 "~하시기 바랍니다" 같은 훈계조는 쓰지 않습니다.
- **구체성**: "비쌌다" 대신 "배송비까지 4만 5천 원", "오래 걸렸다" 대신 "40분쯤 걸렸습니다".
- **솔직함**: 장점만 늘어놓지 않고 아쉬운 점과 실수를 반드시 섞습니다.
- **금지**: 음주 이야기, 가족 실명, 배우자 몰래 샀다는 설정, 집이 좁다는 표현,
  "[사진 넣을 자리]" 같은 표시, "이상으로 알아보았습니다" 같은 상투적 마무리.

### 출력은 HTML 코드가 아닙니다

AI 에게 HTML 코드를 받아 뷰어로 확인하는 방식이 아닙니다. 이 프로그램은 AI 가 준 **글 내용**을
받아서 네이버 에디터에 직접 옮겨 적고, 소제목 크기·문단 간격·표 테두리·강조 서식은
프로그램이 입힙니다. 그래서 AI 에게는 **"HTML 로 만들었을 때 화면에 보이는 글자"만** 달라고
요구합니다. 그래도 모델이 태그를 섞어 보내는 경우가 있어, 받은 뒤에 `<b>` 를 빼고
전부 걷어냅니다 (`stripTags`). 제목과 썸네일 문구는 `<b>` 까지 지워 순수 텍스트로 만듭니다.

## 모델 고르기 — Opus 와 Sonnet 중 무엇을

이 프로그램은 API 종량과금이 아니라 **`claude` CLI 에 로그인된 구독 계정**을 씁니다.
그래서 따질 것은 요금이 아니라 **구독 사용량 한도를 얼마나 빨리 쓰느냐**입니다.

같은 주제(`겨울철 아파트 난방비 아끼는 방법`)로 직접 재봤습니다.

| | Sonnet 5 | Opus 5 |
|---|---|---|
| 품질 검사 | 19/19 통과 | 19/19 통과 |
| 자동 보정 | 0회 | 0회 |
| 분량 | 3,279자 | **4,197자** (+28%) |
| 인용한 출처 | 4개 | **6개** (+50%) |
| 걸린 시간 | 170초 | 227초 |

**검사 점수는 똑같습니다.** 품질 검사는 바닥을 지키는 장치이지 천장을 올리지 못합니다.
차이는 검사 위쪽에서 납니다.

- Opus 는 출처를 문장 안에 녹입니다 —
  *"서울시 환경 소식 자료를 보면 에어캡을 붙이고 문틈에 문풍지를 대는 것만으로 10에서 20퍼센트까지 아낄 수 있다고 나옵니다"*
- Opus 는 실패를 소제목에 씁니다 — *"제도 쪽에서 챙길 게 있나 찾아보다가 헛물도 켰습니다"*
  (페르소나 지침이 요구하는 "감정의 고저"를 실제로 구현한 대목입니다)

**글 품질이 시간보다 중요하다면 본문은 Opus 가 맞습니다.**

### 다만 표의 행까지 Opus 로 채울 필요는 없습니다

표 행 채우기는 이름을 나열하는 일이라 판단력이 거의 필요 없습니다.
`전국 4년제 대학교 순위` 로 50행을 채워 재봤습니다.

| 모델 | 채운 행 | 빈칸 | 시간 |
|---|---|---|---|
| Haiku 4.5 | 50/50 | 0개 | 80초 |
| Sonnet 5 | 50/50 | 0개 | 51초 |
| Opus 5 | 50/50 | 0개 | 34초 |

**결과가 같습니다.** 그런데 TOP100 글은 호출 5~6번 중 4~5번이 표 행 채우기입니다.
여기만 싼 모델로 내리면 **본문 품질은 그대로 두고 사용량을 크게 아낄 수 있습니다.**

그래서 설정을 둘로 나눴습니다.

| 설정 | 기본값 | 무엇에 쓰이는지 |
|---|---|---|
| 사용할 AI 모델 | CLI 기본값 | 본문·도입·마무리·품질 보정 — **여기에 Opus 를 넣으세요** |
| 표의 행을 채울 모델 | `claude-sonnet-5` | 표의 행만. 본문 품질과 무관합니다 |

"본문과 같은 모델 사용"을 고르면 예전처럼 하나로 돌아갑니다.

## 웹 검색 — 근거 있는 글의 조건

기본으로 **켜져 있습니다.** 글을 쓰기 전에 AI가 직접 자료를 검색하고, 확인한 수치만 출처와 함께 씁니다.

```
[INFO] 자료를 검색해서 확인하며 씁니다. 이 단계가 1~3분 더 걸립니다.
```

끄면 AI가 자기 기억에만 의존하고, 프롬프트도 **"수치를 지어내지 말라"** 는 쪽으로 바뀝니다.
안전하긴 하지만 근거가 사라져서 누구나 쓸 수 있는 뻔한 글이 됩니다.

- 검색은 **본문을 쓸 때 한 번만** 씁니다. 표의 행을 채울 때와 품질 보정에는 쓰지 않습니다.
  (TOP100 표를 행마다 검색하면 한 편에 수십 분이 걸립니다)
- 확인한 자료는 글 맨 끝 **"참고한 자료"** 목록으로 남습니다.
- 검색을 켜도 `claude` 에는 **WebSearch 하나만** 열어줍니다. Bash 같은 실행 도구는 그대로 막혀 있습니다.
- 100개를 한 번에 돌릴 때 시간이 부담되면 설정에서 끄고, 중요한 글만 켜서 돌리셔도 됩니다.

## 글 품질 검사 (자동 보정)

글이 다 써지면 곧바로 아래 규칙을 자동으로 점검합니다. **규칙은 프롬프트 지시문이자
검사 기준으로 한 곳에서 관리됩니다** (`src/content/quality.js`) — 그래야 "규칙은 넣었는데
안 지켜진 글"이 생기지 않습니다.

| 검사 항목 | 확인하는 것 |
|---|---|
| 분량 | 공백 제외 최소 글자 수를 채웠는지 |
| 종결어미 | 완전한 문장으로 끝났는지, 개조식("~함/~임")을 안 썼는지 |
| 사람 말투 | "~네요", "~더라고요", "~거든요" 같은 구어체 어미가 충분히 섞였는지 (독백체일 때) |
| 금지 표현 | 음주 이야기, 사진 자리 표시, 몰래 샀다는 설정, 집이 좁다는 표현, 가족 실명, 상투적 마무리가 없는지 |
| 번역투 접속사 | "결론적으로", "무엇보다도", "한편", "게다가" 같은 기계적인 접속사를 안 썼는지 |
| 문단 길이 | 한 문단이 너무 길지 않은지 (모바일에서 읽기 때문에 2~3문장씩 끊어야 합니다) |
| 구체적인 숫자 | 가격·시간·개수를 숫자로 짚은 대목이 5군데 이상인지 |
| 솔직한 아쉬움 | 장점만 늘어놓지 않고 아쉬운 점이나 주의할 점을 적었는지 |
| 생활 맥락 | 쓰는 사람의 일상(퇴근, 육아, 주말)이 배경으로 깔렸는지 |
| 신뢰도 장치 | 본론 전에 오해를 짚었는지(disclaimer), 글 끝에 자료 성격을 밝혔는지(footnote) |
| 체크리스트 표 | 마무리 직전 "이것까지 같이 보세요" 표가 4줄 이상인지 |
| 소제목 말투 | 소제목이 "개요", "1. 특징" 같은 명사 나열이 아니라 문장인지 |
| 다음 글 예고 | 마무리에 이어서 쓸 글을 예고했는지 |
| 소제목 구조 | 소제목 3개 이상 + 세부 소제목이 있는지 |
| 선정 기준 | (켰다면, 순위·비교 글에서) 서두에 고른 기준을 밝혔는지 |
| 비교 표 | 표가 2행×2열 이상 있는지 |
| 불렛 포인트 | 목록이 최소 1개 있는지 |
| 항목별 상세 | (TOP5~12 같은 항목형 글) 항목마다 세부 소제목이 3개 이상인지 |
| 서두 인사말 금지 | "안녕하세요", "이번 포스팅에서는" 없이 바로 본론으로 시작하는지 |
| 기호·이모지 | 본문에 장식 기호(★, ※ 등)나 이모지가 없는지 |
| 마무리 | 억지 요약 없이 덤덤하게 끝냈는지 |

**걸린 항목만 짚어 다시 쓰게 합니다.** 통과한 부분은 그대로 두고, 미통과 항목의 구체적인
이유("공백 제외 1,340자 / 필요 1,800자 — 460자가 부족합니다" 등)를 담아 재요청합니다.
보정 후에도 더 나빠졌으면 원래 글을 그대로 씁니다.

작업표의 **품질** 열에 `10/10` 처럼 뜨고, 마우스를 올리면 항목별 통과 여부가 보입니다.
`data/posts/<주제-id>/preview.html` 에도 검사 결과가 전부 남습니다.

## 이미지 — 상단 썸네일 + 본문 강조 카드 3장

기본은 **HTML/CSS 템플릿을 Playwright로 스크린샷** 찍는 방식이라 추가 비용이 0원입니다.
여기에 **상단 썸네일의 배경 그림 한 장만** 이미지 생성 AI로 그리는 선택지를 더했습니다.

### 만드는 방식 두 가지

| 방식 | 어떻게 | 결과 |
|---|---|---|
| **AI가 통째로** (기본) | 한글 문구까지 그림 안에 그려 달라고 요청 | 광고 배너처럼 화려함. 드물게 한글이 뭉개질 수 있음 |
| **배경만 AI** | 글자 없는 배경만 받고 한글은 프로그램이 얹음 | 한글이 절대 안 깨짐. 대신 덜 화려함 |

기본은 **AI가 통째로** 입니다. 넣을 문구를 따옴표로 묶어 "글자 그대로, 번역하지 말고,
다른 말 붙이지 말고" 그리라고 못 박아서 보냅니다.

```
Render the following KOREAN text inside the image, spelled EXACTLY
character for character, with no changes, no translation, no extra words:
  MAIN HEADLINE (largest, most prominent): "4년제만 답이 아니다"
  SUB HEADLINE (on a ribbon banner below): "실무 자격증 현장경험 빠르게 취업하는 비결"
  SMALL CORNER BADGE: "2026 최신"
```

**한글이 뭉개져 나오면** 설정의 **썸네일 만드는 방식**을 `배경만 AI` 로 내리세요.
한글은 브라우저가 그리므로 깨질 수가 없습니다.

- 그림을 못 받아오면(키 없음·한도 초과·오류) **기존 HTML 썸네일로 자동으로 되돌아갑니다.**
  실행이 멈추지 않습니다.
- 통째로 받은 그림은 **다시 그리지 않고 그대로 저장합니다.** 재가공하면 화질만 깎입니다.

### 켜는 법

1. [aistudio.google.com](https://aistudio.google.com) 에서 API 키를 발급받습니다
2. 설정에서 **"상단 썸네일 배경을 이미지 생성 AI로 그리기"** 를 켜고 키를 붙여넣습니다
3. **[이미지 API 테스트]** 를 눌러 한 장 뽑아봅니다 (결과 그림이 화면에 바로 뜹니다)

키는 `data/settings.json` 에만 저장되고, 이 폴더는 `.gitignore` 대상이라 저장소에 올라가지 않습니다.

대략 장당 $0.05~0.07, **글 100편에 7천원선**입니다.
(가격은 자주 바뀌니 [구글 AI 가격 페이지](https://ai.google.dev/pricing)에서 확인하세요)

### 모델은 고를 필요가 없습니다

구글은 **Imagen 4 계열(`imagen-4.0-*`)을 2026년 8월 17일에 종료**했습니다.
후속인 Gemini 이미지 모델은 호출 형식까지 다릅니다 (`:predict` → `:generateContent`).
한 번 통째로 갈아엎은 전례가 있으니, **모델 이름을 사람이 관리하지 않기로 했습니다.**

돌릴 때마다 계정에서 쓸 수 있는 모델 목록을 받아서 **가장 싼 것을 자동으로 고릅니다.**

```
[INFO] 이미지 모델을 자동으로 골랐습니다: gemini-3.1-flash-image
```

고르는 기준입니다.

1. 이름에 `image` 가 있는 **이미지 생성** 모델만 후보로 둡니다
2. `ultra` 등급은 제외합니다 (가장 비쌉니다)
3. `flash` 를 가장 먼저 고릅니다 (가장 쌉니다). `pro` 는 맨 뒤로 밉니다
4. 같은 등급이면 정식 버전을 preview 보다 먼저, 최신 버전을 먼저 고릅니다

**항상 가장 싼 것을 고릅니다.** 품질을 위해 비싼 등급을 쓰는 선택지는 두지 않았습니다.

- 골라둔 모델이 **없어지면(404) 캐시를 비우고 다음 글에서 다시 고릅니다.**
- 호출 형식은 이름으로 자동 판별합니다 — `imagen` 으로 시작하면 옛 형식, 아니면 현행 형식.
- 목록조차 못 받아오면 `gemini-3.1-flash-image` 로 한 번 시도합니다.
- 어떤 경우든 그림을 못 받으면 **기존 HTML 썸네일로 되돌아가므로** 실행은 멈추지 않습니다.

특정 모델을 고집하고 싶을 때만 `data/settings.json` 의 `image.model` 에 이름을 적으면
그 모델을 씁니다. (종료된 `imagen-4.0-*` 를 적어두면 무시하고 다시 고릅니다)

**본문 강조 카드 3장은 이 기능을 쓰지 않습니다.** 지금처럼 HTML 캡처로 공짜로 만듭니다.
돈이 드는 건 글 한 편당 배경 그림 한 장뿐입니다. 꺼두면 지금까지와 완전히 똑같이 동작합니다.

### 글자를 얹는 템플릿

배경 그림이 없을 때는 기존 4종(bold / gradient / minimal / editorial)을 쓰고,
광고 배너처럼 두 단으로 짜서(큰 헤드라인 + 하단 강조 띠) 눈에 띄게 만들었습니다.

- **상단 썸네일**: 도입부 직후, 글 상단 1/3 안에 들어갑니다. 제목 문구 + 하단 강조 띠(부제)
- **본문 강조 카드 3장**: 글의 **1/5·중간·4/5 지점**에 들어갑니다. 실제 사진 대신, 그 지점의
  핵심 문구(선정 기준 / 비교표 대표 행 / 마무리 요약 등 — 이미 써진 내용에서 그대로 뽑습니다)를
  카드 형태로 시각화합니다. AI 호출을 추가로 쓰지 않아 비용과 시간이 늘지 않습니다.
- 글이 짧아 카드 후보가 부족하면 3장보다 적게 나올 수 있습니다 — 없는 내용을 억지로
  만들어내지 않습니다. 이 경우 그 지점은 이미지 없이 자연스럽게 이어집니다.
- 설정에서 강조 카드 삽입을 끌 수 있습니다.

## 순위·목록형 글 (TOP100 등)

주제에서 글의 "모양"을 자동으로 정합니다 (`src/content/ranking.js` 의 `detectShape`).

| 모양 | 언제 | 어떻게 쓰는지 |
|---|---|---|
| **항목별 상세형** | 개수가 12개 이하 (`TOP5`, `7가지`) 또는 "추천/비교/고르는" 성격의 글 | 항목마다 섹션 하나 + 세부 소제목을 씁니다. 한 번의 호출로 끝냅니다 |
| **대형 비교표형** | 개수가 13개 이상 (`TOP50`, `100가지`), 또는 **개수 없이 "순위/랭킹/베스트"** 라고만 쓴 주제 | 본문은 짧게, 큰 표 하나에 항목을 전부 담습니다. 표는 따로 나눠 받습니다 |
| **정보 정리형** | 개수도 순위 성격도 없는 일반 주제 | 소제목 중심으로 씁니다 |

**표는 최대한 많이 채웁니다.** `TOP100` 이면 100개를 목표로 하고, 개수를 안 밝힌
`"OO 순위"` 도 **기본 100개**를 목표로 잡습니다. (설정의 "순위 글 표 크기", 최대 300)

뒤쪽 구간에서는 **범위를 넓히라고 따로 일러줍니다.** 유명한 것은 앞 구간에서 이미
다 나갔기 때문에, 그대로 두면 뒤쪽이 텅 빕니다. 그래서 25개씩 끊어 받으면서
구간이 뒤로 갈수록 "덜 알려진 곳, 지방·지역에 있는 곳, 규모가 작은 곳,
전문·특수 분야까지 넓혀서 채우라"고 요구합니다.

실제로 `2026 전국 4년제 대학교 순위` 를 돌리면 이렇게 나옵니다.

```
  1: 서울대학교      |  30: 광운대학교    |  60: 한국해양대학교(부산)
 61: 목포대학교      |  80: 동의대학교    | 100: 서원대학교(청주)
```

자료가 모자라면 확인되는 데까지만 넣고 **빈 행을 지어내지 않습니다.**
이때는 번호를 1부터 다시 매겨 표에 구멍이 생기지 않게 하고,
표 아래에 "확인할 수 있는 자료가 있는 N개까지 정리했습니다" 라고 밝힙니다.

대형 비교표형은 한 번의 호출로 100행을 받으면 모델이 "이하 생략" 하거나 출력 길이에
걸려 잘리므로 나눠 받습니다.

1. 글의 뼈대와 표의 열 구성을 먼저 받습니다
2. 표의 행을 **25개씩 끊어서** 받습니다 (한 번에 많이 달라고 하면 뒤쪽을 흐지부지 끝냅니다)
3. 1위부터 N위까지 빠진 번호가 있으면 **그 구간만 다시** 받습니다
4. 그래도 빈 곳이 있으면 작업표와 로그에 "누락 N건"으로 표시합니다

| 항목 수 | 호출 횟수 | 대략 걸리는 시간 |
|---|---|---|
| TOP12 이하 | 1~2회 (품질 보정 포함) | 약 1~3분 |
| TOP50 | 3~4회 | 약 3~5분 |
| TOP100 | 5~6회 | 약 5~8분 |

웹 검색을 켜면 본문 호출에서 1~3분이 더 붙습니다. 100개 주제를 한 번에 돌리실 때는
**순위 글 표 크기를 줄이거나 웹 검색을 끄는 편**이 현실적입니다.

표는 첫 소제목 다음에 들어갑니다.

> **중요 — 이 표는 공식 순위가 아닙니다.**
> AI 는 실시간 검색을 하지 않습니다. "어린이집 만족도 TOP30" 같은 주제에는 애초에
> 공개된 공식 순위가 없습니다. 그래서 이 프로그램은 표를 **"일반적으로 알려진 정보를
> 모아 정리한 참고용 자료"** 로 만들고, 표 아래에 그 사실을 밝히는 안내문을 반드시 넣습니다.
> 없는 조사 결과를 사실처럼 쓰라고 요구하면 AI 가 작성을 거절합니다.
> 발행 전에 내용을 직접 확인하세요.

## 참고 예시 글

"이런 식으로 써줘" 하고 보여줄 글을 올리면 AI 가 문체·문단 길이·소제목 방식·마무리 방식을
참고합니다. 내용을 베끼지는 않습니다.

- `txt` / `md` / `html` / `csv` / `json` 파일을 첨부하거나 직접 붙여넣습니다
- 여러 개 올려두고 체크박스로 켜고 끌 수 있습니다
- 한 개당 최대 20,000자, 전체 합쳐 24,000자까지 프롬프트에 들어갑니다 (넘치면 잘립니다)
- 저장 위치: `data/examples/`

## 적용되는 서식

AI 응답을 HTML로 조립해 에디터에 붙여넣습니다.

- 소제목 (19px 굵게, 위아래 여백) + 세부 소제목 (왼쪽 초록 띠, 한 단계 작게)
- 본문 문단 (16px, 줄간격 1.9) + 문단 사이 빈 줄
- 문단 내 핵심 문구 **굵게**
- 선정 기준 단락, 항목 목록, 초록 세로선 인용구
- 표 (순위표·비교표 등) — 머리글 음영, 줄무늬 배경, 테두리
- 섹션 사이 `• • •` 구분선
- 마지막에 해시태그 줄

붙여넣기는 3단계로 시도합니다: 합성 paste 이벤트 → 실제 클립보드 + Ctrl+V → 평문 타이핑.
앞의 방법이 막히면 자동으로 다음 방법으로 넘어갑니다.

본문은 조각 단위(선정 기준 → 섹션들 → 표 → 마무리)로 쪼개서 순서대로 붙여넣고,
그 사이사이 1/5·중간·4/5 지점에서 멈춰 강조 카드 이미지를 끼워 넣습니다.
100행짜리 표나 이미지 여러 장이 들어간 글을 한 번에 밀어 넣으면 에디터가 버거워하기 때문입니다.

## 다른 네이버 계정으로 바꿀 때

블로그 아이디는 로그인한 계정을 따라갑니다. 계정을 바꾸면 자동으로 다시 확인합니다.

1. **[세션 삭제]** — 이전 세션과 블로그 아이디를 비웁니다
2. **[네이버 로그인 창 열기]** — 새 계정으로 로그인
3. 상단 뱃지가 `네이버 로그인됨 · 새아이디` 로 바뀌는지 확인

[세션 삭제]를 건너뛰고 로그인해도 됩니다. 로그인할 때와 실행을 시작할 때
블로그 아이디를 다시 확인하고, 바뀌었으면 로그에 이렇게 남깁니다.

```
블로그 아이디가 바뀌었습니다: 이전아이디 → 새아이디
대상 블로그: 새아이디
```

> 아이디가 맞지 않으면 글쓰기 화면 대신 **그 블로그 홈**이 열립니다.
> 남의 블로그에는 글을 쓸 수 없기 때문입니다. 이 경우 프로그램이 주소를 바꿔가며
> 다시 시도하고, 마지막에는 블로그 화면의 글쓰기 버튼을 눌러봅니다.

## 속도·토큰과 품질의 줄다리기

`claude -p` 는 **호출 한 번당** CLI 자체 시스템 프롬프트로만 3만 토큰 넘게 씁니다.
따라서 글자 수보다 **호출 횟수**가 비용을 좌우합니다. 품질 검사의 자동 보정도 걸리면
호출을 한 번 더 씁니다 — 기본값은 글 품질을 우선하도록 맞춰져 있습니다.

| 상황 | 설정 | 효과 |
|---|---|---|
| 기본값 (품질 우선) | 분량 1800자, 소제목 4개, 보정 1회 | 애드센스 승인 수준을 겨냥합니다. 글 하나에 호출 2~3회 |
| 빠르게 많이 돌리고 싶을 때 | 분량 1000~1200자, 소제목 3개, 보정 0회 | 호출이 줄어 빠르지만 품질 검사를 통과 못 해도 그대로 저장됩니다 |
| 사용할 AI 모델 | Haiku 4.5 | 가장 빠릅니다. 품질이 아쉬우면 Sonnet 5나 Opus 5 |
| 참고 예시 | 필요할 때만 켜기 | 예시는 호출마다 프롬프트에 실려 갑니다 |
| 주제의 항목 수 | 12 이하 | 13개부터는 표를 나눠 받느라 호출이 늘어납니다 |

품질 검사를 끄고 싶으면 설정에서 "품질 검사 자동 보정"을 끄면 됩니다 — 검사 결과는
계속 작업표에 표시되지만 다시 쓰게 하지는 않습니다.

## 실행이 자꾸 실패할 때

먼저 **설정 → [선택한 모델로 연결 테스트]** 를 눌러보세요. 주제를 100개 돌리기 전에
지금 고른 모델로 실제 호출이 되는지 한 번에 확인할 수 있습니다.

| 증상 | 원인과 해결 |
|---|---|
| `모델을 쓸 수 없는 플랜일 수 있습니다` | 구독 플랜에서 그 모델을 못 씁니다. 설정에서 Sonnet 5 나 기본값으로 바꾸세요 |
| `사용량 한도에 걸린 것 같습니다` | 구독 사용량을 다 썼습니다. 자동으로 일시정지되니 잠시 뒤 [이어서 실행]을 누르세요 |
| `claude CLI 를 찾을 수 없습니다` | `npm install -g @anthropic-ai/claude-code` 후 `claude` 로 한 번 로그인하세요 |
| `연속 3건이 같은 이유로 실패해 실행을 멈춥니다` | 설정이 잘못됐다는 뜻입니다. 남은 주제를 태우지 않으려고 멈춘 것이니 오류 내용을 먼저 보세요 |
| `AI가 이 주제로 글쓰기를 거절했습니다` | 없는 조사 데이터를 사실처럼 요구하는 주제입니다. 주제를 바꾸거나(예: "고르는 기준 TOP30") 추가 지침에서 "참고용 정리"임을 명시하세요 |

오류 원문은 `data/logs/claude-fail-*.log` 에 그대로 남습니다.

## 자동화가 깨졌을 때

네이버 스마트에디터는 클래스 이름에 해시가 붙어 수시로 바뀝니다.
"요소를 찾지 못했습니다" 오류가 나면 **`src/naver/selectors.js`** 의 후보 목록에
현재 화면의 선택자를 추가하면 됩니다. 각 항목은 후보 배열이라, 맨 앞에 하나 끼워 넣기만 하면 됩니다.

실패 시점의 화면은 `data/screenshots/` 에 저장되니 어디서 막혔는지 바로 확인할 수 있습니다.

## 알아두실 점

- 발행이 아니라 **임시저장**만 합니다. 글의 사실관계와 최종 품질은 사람이 확인하고 발행하세요.
- 짧은 시간에 많은 글을 자동으로 올리면 비정상 트래픽으로 보일 수 있습니다.
  기본 대기 시간(30~90초)을 너무 줄이지 말고, 한 번에 처리하는 양도 나눠서 돌리시길 권합니다.
- 아이디·비밀번호는 프로그램이 저장하거나 전송하지 않습니다. 다만 **로그인 쿠키는
  `data/naver-cookies.json` 에 평문으로 남습니다.** 크로미움이 프로필 폴더에 쿠키를
  제때 기록하지 않아 로그인이 자꾸 풀리는 문제를 막기 위한 것입니다. 이 파일은
  git 에 올라가지 않지만, 다른 사람과 공유하는 컴퓨터라면 쓰고 나서 [세션 삭제]를
  눌러 지우시는 편이 안전합니다.
